# Gemma 생성 태그의 내용 필터 제거 — 0.2.6

2026-11-04. Gemma TIPO의 태그 후처리는 중복 제거만 수행한다.
`max_added_tags`로 지정한 추가 개수 제한과 원문 보존은 유지한다.

## 변경 이유

기존 코드는 중간 영어 설명의 단어 집합과 태그의 단어 집합을 비교했다.
설명에 그대로 등장하지 않은 조명·의상·소품·동작·위치 표현을 제거했고,
남는 태그가 없으면 실행을 중단했다. `soft lighting`과 `softly lit`처럼
단순한 표현 차이도 허용 목록에 없으면 거절됐다. 확장 모델의 출력을
제한된 수작업 어휘 검사로 다시 판정하는 동작은 제거했다.

공통 설명이 원문에 없던 영문 단어를 추가했는지 확인하는 검사와,
명시적 의상 목록의 영문 문자열이 착용 문장에 그대로 있는지 확인하는
검사도 제거했다. 내용에 대한 단어 비교 때문에 재생성하거나 오류를
내지 않는다. 중간 계획에는 입력 사실을 보존하고 디테일을 확장하도록
계속 요청하지만, 생성된 내용의 채택 여부를 코드가 판정하지 않는다.

## 남겨 둔 처리

- 생성된 태그의 대소문자·공백·밑줄을 정규화해 중복 여부를 비교한다.
  비교할 때만 정규화하며 출력 태그의 표기는 유지한다.
- `(open mouth, determined:1.3)` 내부 태그와 동일한 일반 태그는 중복이다.
  원문의 가중치 묶음과 캐릭터명 괄호 이스케이프는 그대로 보존한다.
- `soft lighting`과 `softly lit`처럼 표현이 다른 태그는 의미를 추측해
  합치거나 제거하지 않는다.
- 캐릭터 설명에 이미 있는 외형·위치 정보는 태그 변환의 접두어로
  유지하지만, 그 접두어와 다른 생성 태그를 내용상의 이유로 제거하지 않는다.
- 영문 원문 뒤에 붙일 새 태그는 중복 제거 후 `max_added_tags`로 제한한다.
  한국어 입력은 기존대로 번역한 출력을 사용한다.
- 잘못된 JSON, 인물 슬롯 개수/자료형, 영어 문장과 태그의 출력 형식,
  자연어 출력의 원문 가중치, 사용자가 지정한 `excluded_tags`는 검사한다.
  형식 오류는 같은 모델로 한 번 재시도하고 실패 응답을 진단에 남긴다.

불필요한 구체적 장면·머리색·의상·소품 예시도 요청에서 제거했다.
JSON 예시는 실제 인물 키와 빈 문자열만 사용한다.

## 검증

Python 회귀 검사 152개와 JavaScript 검사 스크립트 4개를 통과했다.
새 검사는 설명에 없는 새 어휘·소품·의상·위치·역할이 그대로 유지되고,
가중치 내부 태그와 같은 중복만 제거되는지 확인한다. 확장 없는 정상
문장이나 의상 표현의 어휘 차이가 내용 재시도를 일으키지 않는 것도
확인했다. 기존 JSON·형식 재시도, 인물 슬롯, 가중치 및 명시적 제외 태그
검사는 유지된다.

실제 8188 서버에서도 `very_long`, 시드 `4606152648120`,
로컬 학습 LoRA `local:scale-20pct-001`로 다음 두 실행을 완료했다.

| 모델 / 입력 | 결과 | 관찰 |
|---|---|---|
| Q4 / 가중치 묶음을 포함한 2인 입력 | 성공 | 공통은 새 태그 0개로 `unchanged`, 인물별 추가 태그 3개. 내용 필터에 의한 실행 중단 없음 |
| BF16 / 2인 카페 입력 | 성공 | 인물별 새 손동작·시선 표현 유지. 태그 대신 문장이 나온 인물 출력은 한 번씩 형식 재시도 후 통과 |

BF16 공통에 표시된 추가 태그 4개는 원문의 표현을 바꾼 부분도 포함한다.
문자열 추가 개수만으로 실제 새 디테일이 생겼다고 판단하지 않는다.
이 두 실행은 텍스트 생성 검증이며 이미지 생성 검증은 아니다. 배포 기본
어댑터 전부의 품질을 보증하는 시험도 아니다.

이 검증은 의미상 올바른 확장을 보장하지 않는다. 모델이 원치 않는
내용을 생성할 수 있으므로 결과 패널의 원문·출력·모델 응답을 확인한다.
추가 태그 개수는 문자열 기준이며 의미 품질 점수가 아니다.

## 범위와 크레딧

이번 내용 필터 제거는 Gemma TIPO 경로에 적용된다. 독립 TIPO 2.1의
기존 선택형 `protect_source` 동작은 별도다. 모델 가중치, 의존성,
네이티브 모델 자원관리 및 PLE/LoRA 메모리 최적화는 변경하지 않는다.
원본 TIPO 저작자, KohakuBlueleaf와 기여자, Gemma 및 City96의
저작권과 라이선스를 유지한다. [NOTICE](../NOTICE)를 참고한다.
