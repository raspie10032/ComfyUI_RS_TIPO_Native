# Gemma 빈 필드의 원문 복원 — 0.2.10

유효한 JSON에서 Gemma가 `common`을 빈 문자열로 반환하면, 이전 버전은
`Gemma TIPO omitted the common prompt`로 재시도하고 최종 실패했습니다.
캐릭터 문자열이 비어 있어도 슬롯 오류로 처리했습니다.

0.2.10에서는 번호와 문자열 형식이 올바른 필드가 비었을 때 해당 필드의
원문을 복원합니다. 다른 필드에 생성된 설명은 그대로 유지하고 태그 변환
또는 자연어 출력으로 이어갑니다. 캐릭터 번호를 바꾸거나 다른 필드의
내용을 옮겨 채우지 않습니다. 모델 지시에도 빈 문자열 대신 자기 원문을
유지하도록 명시했습니다.

예를 들어 공통 원문이 `cafe, afternoon`이고 모델이 아래처럼 출력하면:

```json
{"common": "", "characters": {"1": "The adult wears a blue jacket and waves."}}
```

공통은 `cafe, afternoon`으로 복원되고 캐릭터 설명은 유지됩니다. 태그 모드는
같은 Gemma 인스턴스로 변환을 계속합니다. 최종 영어 태그의 원문 가중치 보존,
동일 태그 중복 제거와 추가 개수 제한은 기존과 같습니다.

복원이 발생한 모델 호출에는 다음 기록이 추가됩니다. 결과 패널의 모델 상세에서
원본 응답과 함께 확인할 수 있습니다.

```json
{"source_restored_fields": ["common"]}
```

빈 칸 복원은 확장·번역 성공을 보장하지 않습니다. 복원한 필드가 원문 그대로
남을 수 있고, 자연어 모드의 한국어 원문도 그대로 반환될 수 있습니다.
다른 필드의 의미 누락이나 역할 혼동도 이 수정이 판별하지 않습니다.
누락·변경된 캐릭터 키, 문자열이 아닌 값, 복구할 수 없는 JSON 등은 기존의
제한된 재시도 후 오류로 남습니다. 사용자가 지정한 제외 태그도 유지합니다.

회귀 검사는 0·1·2·10인, 두 출력 형식, 빈 공통·캐릭터·공백 문자열, 한국어,
원문 가중치, 다른 필드 보존, 복원 기록, 잘못된 슬롯 구조와 명시적 제외 태그를
확인합니다. 공개 노드 경로에서는 빈 공통의 복원 후 가중치가 보존되고 새 태그가
추가되는 것도 검사합니다. 이는 고정 응답을 사용하는 회귀 검사이며, 실제 모델의
빈 응답 발생률을 측정한 결과는 아닙니다.

메인 ComfyUI 8188에서도 서로 다른 입력·시드 64건(Q4 16건·BF16 48건)을
실행해 전부 완료했습니다. 0·1·2·10인, 태그·자연어, 한국어, 원문 가중치와
TIPO LoRA를 포함했습니다. 불완전한 JSON 2건은 기존 재시도로 복구됐고
최종 실패는 없었습니다. 이 연속 실행에서는 빈 필드 복원이 발생하지 않아,
해당 경로는 앞의 고정 응답 회귀 검사와 실제 실패 응답의 파서 재생으로
확인했습니다. 실패 로그의 원래 공통 입력은 남아 있지 않아 파서 재생에는
일반 공통 원문을 사용했습니다. 이미지 생성은 실행하지 않았습니다.

TIPO 원저자, KohakuBlueleaf 및 기여자, Gemma와 City96 기여자의 크레딧과
라이선스는 기존대로 유지합니다. 의존성이나 모델 가중치 변경은 없습니다.
