# Gemma JSON·가중치 오류 수정 — 0.2.3

2026-11-04, 실행 중인 ComfyUI 8188에서 확인한 오류를 수정했다.

## 원인과 수정 범위

ComfyUI 캐릭터명에 쓰는 `\(`, `\)`를 Gemma가 JSON 문자열에 그대로
복사하면 유효하지 않은 JSON 이스케이프가 된다. 토큰 한도 부족과 구분해
실제 JSON 디코더 오류를 표시하고, 중간 자연어 입력에서는 괄호 이스케이프를
제거한다. JSON 파싱은 엄격하게 유지하며, 잘못된 응답은 같은 모델로 한 번
재시도한다. 일반 입력의 기존 지시는 유지하고, 백슬래시가 있을 때만 추가
이스케이프 안내를 넣는다.

영문 태그 입력의 중간 장면 계획에는 가중치를 푼 의미를 전달한다. 최종 노드
출력에서는 원본 영문 프롬프트를 접두부로 보존한다. 따라서 캐릭터명,
이스케이프, 가중치 값, 쉼표가 포함된 가중치 묶음이 남는다. 직접 자연어
출력에서 `(a blue jacket:1.1)`처럼 원본 묶음 안에 관사만 추가된 경우에는
원본 `(blue jacket:1.1)`를 유지하고 관사를 괄호 밖으로 옮긴다. 다른 단어나
숫자가 바뀐 경우에는 해당 필드와 필요한 원문을 명시해 재시도한다.

태그 변환에서 완전한 문장을 그대로 반환한 경우에는 태그 형식으로 재시도한다.
태그 분리·중복 제거·추가 개수 제한은 괄호 안의 쉼표를 구분자로 취급하지 않는다.

## 검증

- 배포 코드 Python 검사 139개, JavaScript 검사 스크립트 4개 통과.
- 별도 개발 트리 검사 229개 중 222개 통과, 선택 의존성 관련 7개 제외.
  기존 학습용 개발 컨트롤의 요청 문자열은 변경하지 않았다.
- 실제 ComfyUI 노드 API로 두 인물, 백슬래시 괄호 캐릭터명, 개별 의상 가중치,
  `(smile, blush:1.5)`와 `(off-shoulder top, a-line skirt:1.8)`를 포함한 입력 실행.
- `scale-20pct-001` LoRA와 BF16·Q4 각각 실행 성공. 공통 프롬프트와 인물별
  최종 출력에 원본 이름·이스케이프·가중치 묶음이 유지됨을 확인.

이 검증은 텍스트 생성의 오류 재현과 수정 확인이다. 모든 입력·시드에서의
의미 정확도나 후속 이미지 품질을 보장하지 않는다. 일부 추가 태그에 의미상
중복이나 어색한 구문이 남을 수 있다. 0.2.2의 PLE·LoRA·역양자화 최적화는
유지하며, 이 패치에서 별도 속도·메모리 개선을 주장하지 않는다.

원본 TIPO 저작자, KohakuBlueleaf와 기여자, Gemma 및 City96 저작권과
라이선스는 그대로 유지한다. [NOTICE](../NOTICE)를 참고한다.
