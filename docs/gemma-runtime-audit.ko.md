# Gemma 실행 경로 점검 — 0.2.11

2026-11-05. 반복 중단이 발생한 Gemma TIPO의 입력 → 모델 로딩 → 생성 → JSON
파싱 → 동일 모델 재시도 → 캐릭터별 태그 변환 → 원문 보존 → 결과 패널 경로를
점검했습니다. 원본 TIPO의 로딩·생성·공통 인터페이스와 다운로드·Q4/LoRA·UI
회귀 검사도 포함했습니다. 추론 엔진이나 모델 가중치를 교체한 변경은 아닙니다.

## 확인한 중단 경로와 변경

| 경로 | 기존 동작 | 0.2.11 동작 |
| --- | --- | --- |
| 완성된 JSON 뒤 여분 `}`·`]` | JSON 파싱 실패 후 같은 형식이 반복되면 중단 | 단일 완성 문서 뒤 닫는 괄호만 남았을 때 복구. 후속 문서나 설명을 버리지는 않음 |
| 잘못된 이스케이프·마지막 쉼표·코드 블록 | 일부 형식만 복구 | 문자열 내용을 유지하며 명확한 표기 오류만 복구 |
| 빈 응답·출력 토큰 상한 | 생성 함수에서 즉시 예외, 형식 재시도에 도달하지 못함 | `finish_reason` 기록 후 파서에 전달. 완성된 응답은 수용하고 불완전 응답은 재시도 |
| 반복된 JSON/슬롯/가중치 오류 | 두 번째 실패에서 전체 노드 중단 | 같은 모델로 1회 교정 후 명확한 번호의 유효한 필드는 보존, 실패한 칸은 그 칸 원문으로 복구 |
| 캐릭터 목록·중복 JSON 키·알 수 없는 번호 | 중복 키는 JSON 디코더가 덮어쓸 수 있음 | 번호를 추측하거나 재배치하지 않음. 모호한 문서는 원문으로 복구 |
| 빈 태그·잘못 감싼 태그 | 태그 단계의 실패로 전체 작업 중단 | 같은 모델로 1회 재시도 후 그 칸의 설명을 유지. 문자열/문자열 배열/단일 `tags` 값은 해제 |
| 자동 접두어와 사용자 제외 태그 충돌 | 프로그램이 넣은 접두어 때문에 최종 출력에서 중단 가능 | 제외된 자동 접두어는 추가하지 않음. 명시적 원문·제외 목록 모순은 모델 로딩 전에 안내 |
| 원문으로 복구된 한국어 | `translated`로 표시될 수 있음 | 동일 한국어는 `unchanged`, 한국어가 남은 수정은 `rewritten`으로 구분 |

`warnings`, `calls`, `json_repairs`, `source_restored_fields`, `finish_reason`,
슬롯별 `recovery_actions`에 처리 결과를 남깁니다. 결과 패널에 복구 경고 수를 표시하고,
모델 상세에서 원문·출력·원시 응답을 확인할 수 있습니다.

## 보존하는 계약과 한계

- 새 어휘·문장·소품·위치·행동을 판별해서 거르는 내용 필터를 추가하지 않습니다.
  기존 중복 정리, 원문 가중치 보존, 사용자가 지정한 제외 태그와 추가량 설정을 유지합니다.
- 원문 복구는 확장·번역 성공을 뜻하지 않습니다. 복구한 칸은 확장되지 않거나
  한국어가 남을 수 있고, 태그 변환 복구 시 자연어 설명이 나올 수 있습니다.
- 캐릭터 번호가 유효해도 모델의 의미·역할·외형 해석까지 보장하지는 않습니다.
  JSON 복구와 슬롯 보존은 이미지의 인물 수 보장이 아닙니다.
- CUDA 메모리 부족, 모델/파일/의존성 문제, 사용자 중단은 성공으로 바꾸지 않습니다.
  재시도는 생성 내용/형식의 문제에만 적용하며 각 단계에서 최대 1회입니다.
- ComfyUI 모델 관리, PLE 최적화, GGUF 연산과 LoRA 적용 경로, 의존성은 변경하지 않습니다.
  모델 생성이 느리거나 실제 메모리가 부족한 경우를 이 변경이 해결하지는 않습니다.

## 검증

로컬 ComfyUI 8188의 실제 API 대기열에서 다음 실행을 완료했습니다.

| 검사 | 결과 |
| --- | --- |
| Python 회귀 검사 | 187개 통과 |
| JavaScript 인터페이스·소켓·다운로드·결과 패널 검사 | 스크립트 4개 통과 |
| Gemma 실제 GPU 텍스트 실행 | Q4 22회 + BF16 22회, 총 44회 완료, 최종 중단 0회 |
| 인원수 | 두 모델 각각 공통 전용 0인 및 1~10인 모두 확인 |
| 입력과 출력 | 영어·한국어, 태그·자연어, 원문 가중치 묶음과 원문 보존 확인 |
| 일반 토큰 한도 | 2,048~4,096 토큰 38회, 복구 경고 0회 |
| 의도적인 낮은 토큰 한도 | 256 토큰 6회 중 10인 2회가 JSON 잘림 후 원문 복구, 나머지 4회 경고 없음 |
| 원본 TIPO 2.1 | 공통 + 1인 실제 텍스트 실행 1회 완료 |
| 이번 실제 오류 응답 재생 | 완성된 문서 뒤의 여분 닫는 괄호를 `extra_closing_delimiters`로 복구, 2인 슬롯 유지 |

44회 중 42회는 복구 경고가 없었고 2회는 원문 복구 경고가 있었습니다. 원문 복구를
확장 성공으로 집계하지 않았습니다. 여분 괄호·잘못된 이스케이프·빈 응답·중복 키·
슬롯 누락·태그 변환 실패·사용자 중단 및 런타임 예외는 별도 회귀 검사로 재현했습니다.
여분 괄호 복구가 44회의 새 모델 응답에서 자연 발생한 것은 아닙니다.

이번 실제 실행은 텍스트 출력까지의 검증입니다. 생성 이미지 품질, 인물 수 정확도,
장시간 무오류, 다른 GPU·Windows 환경까지 검증했다는 뜻은 아닙니다.
