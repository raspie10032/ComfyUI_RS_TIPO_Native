# Gemma 공통 문자열 JSON 복구 — 0.2.8

2026-11-05. 공동 계획에서 Gemma가 공통 설명의 따옴표를 일찍 닫고
뒤에 조명 설명을 계속 쓰는 경우가 있었다. `json.loads`가 구분자를
기대하는 위치에 문장이 남아 실행이 중단됐다. 태그 내용 필터와는 다른 오류다.

전체 캐릭터 객체가 별도로 유효한 JSON이고 공통 필드와의 경계가 명확한
경우에만 공통 문자열의 따옴표·구분자·줄바꿈 표기를 복구한다. 중간
따옴표 뒤의 문장을 버리거나 캐릭터 설명을 다시 만들지 않는다. 내부
따옴표도 문자열 내용으로 보존한다. 모호한 추가 필드, 잘린 객체, 잘못된
캐릭터 JSON을 추측해 채우지는 않는다.

그 밖의 JSON 문법 오류는 같은 모델에 기존 응답과 필요한 빈 JSON 구조를
전달해 한 번만 형식을 고치도록 요청한다. 이때 원래의 확장 지시를
반복하지 않는다. 새 디테일 추가·요약·번역 없이 형식만 고치도록 한다.
모델이 이 지시를 완벽히 지킨다는 보장은 없으며, 원시 응답은 진단에 남는다.

인물 슬롯·자료형, 원문 가중치, 명시적 제외어 검사는 유지한다. 생성된
태그의 내용 필터를 추가하지 않는다. 기존 중복 제거와 추가 개수 제한은
그대로 적용한다. 모델·의존성·ComfyUI 자원관리 경로는 변경하지 않는다.

회귀 검사는 공통 문자열 오류와 0·1·2·10인 슬롯 보존, 원문 가중치,
정상 JSON의 이스케이프, 잘린 구조의 거절과 한 번의 형식 재시도를 다룬다.
이 검사는 구조 복구 검증이며 이미지 품질이나 모델의 의미 보존을 보장하지 않는다.

로컬 8188의 실제 Q4·BF16에 `scale-20pct-001`을 적용한 2인 태그 생성도
각각 통과했다. 공통·캐릭터 2개 출력과 원문 `(blonde hair:1.2)` 보존을
확인했다. 고장 난 JSON의 복구는 회귀 검사로 재현했고, 실제 생성 검사는
정상적인 전체 텍스트 경로를 확인한 것이다. 이미지 생성은 실행하지 않았다.
