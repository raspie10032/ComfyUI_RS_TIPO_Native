# Gemma 입력 가중치 분리·확장·복구

숫자 가중치를 복사하는 작업은 노드가 맡고, Gemma는 프롬프트의 내용을
번역·확장합니다. 적용 대상은 명시적인 SD `(태그:1.3)`와 NAI
`1.3::태그 ::` 구문입니다. 가중치의 숫자, 표기와 중첩 구조를 보관합니다.
일반 `(강조)`나 `[약화]`, 이스케이프된 캐릭터 이름 괄호는 그대로 둡니다.

1. 각 공통·캐릭터 필드에서 숫자 가중치를 따로 보관합니다.
2. Gemma에는 가중치 없는 태그·문장을 보냅니다.
3. 확장 결과에 원래 가중 구절을 복구하고 같은 태그의 중복을 정리합니다.

예를 들어 다음 입력에서는 숫자와 괄호를 제외한 내용만 모델에 전달합니다.

```text
입력: (open mouth, determined, one eye closed, :1.3), red coat
전달: open mouth, determined, one eye closed, red coat
출력: (open mouth, determined, one eye closed, :1.3), red coat, soft lighting
```

확장 결과가 원래 가중 구절을 누락하거나 바꿔도, 보관한 구절을 복구하고
새 묘사는 유지합니다. 표기가 달라졌다는 이유로 해당 필드 전체를 원문으로
되돌리지 않습니다. 모델이 임의로 생성한 숫자 가중치는 원본 가중치로
취급하지 않습니다. 서로 다른 태그를 의미가 비슷하다는 이유로 삭제하지 않습니다.

자연어 출력에서는 원래 구절이 있는 위치에 가중치를 다시 붙입니다.
원래 구절을 찾을 수 없으면 보관한 가중 구절을 문장 뒤에 추가합니다.

한국어 가중 구절은 같은 Gemma에 묶어서 한 번 번역한 다음, 그 번역을
확장 입력과 가중치 복구에 함께 사용합니다. `(은발:1.3)`은 예를 들어
`(silver hair:1.3)`로 복구됩니다. 가중치 숫자가 같아도 구절별로 연결하므로
캐릭터 간 가중치를 숫자로 추측해 옮기지 않습니다. 번역 실패 시 한국어
가중 구절만 원문으로 보존하고 경고를 기록하며, 생성한 다른 묘사는 유지합니다.
한국어 가중 구절이 있으면 이 번역을 위한 모델 호출이 한 번 추가됩니다.

`expand_common=False`이면 공통 프롬프트는 입력 원문 그대로 반환합니다.
잘못된 JSON, 번호별 필드 오류와 명시적인 `excluded_tags` 충돌 처리는
계속 별도로 적용됩니다.

## 확인한 범위

2026-11-05 RTX 5060 Ti에서 Q4 Gemma와 공개 presampling LoRA 강도 0.25,
temperature 0으로 실제 추론했습니다. 기존 ComfyUI 서버는 재시작하지 않았습니다.

| 입력 | 실제 추론 결과 |
| --- | --- |
| 영어 가중 태그·묶음 태그 | 수정 전은 재시도 후 원문, 수정 후는 1회 호출로 확장·가중치 복구 |
| 한국어 가중 태그·2인 | 머리·눈 가중치 번역과 복구, 주는 쪽·받는 쪽의 텍스트 확장 유지 |
| NAI 가중치·배경만 | 원래 `1.25::misty forest ::` 유지, 추가 배경 태그 6개 |
| 자연어·가중 태그 | 확장 문장 안에 `(silver hair:1.3)` 복구 |

테스트 종료 시 테스트 프로세스의 GPU 할당은 32 MiB, 로드 모델은 0개였습니다.
번호별 10인 가중치 분리와 번역 실패 복구는 자동검사로 확인했습니다.
이번 실제 추론은 텍스트 검사이며 10인 실추론이나 이미지 품질 평가는 아닙니다.

이 기능은 RS 노드의 입력·출력 처리입니다. TIPO 원저자와 KGen 기여자,
Gemma를 공개한 Google DeepMind를 비롯한 기존 원저작자·라이선스 고지는
프로젝트의 NOTICE와 각 모델 카드에 유지합니다.
